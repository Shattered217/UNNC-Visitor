# 部署与配置

首次安装见 [README](../README.md)，邮箱部署和账号设置见 [Cloud Mail 接入](mail-api.md)。本文说明日常配置和维护。

## 运行结构

| 组件 | 运行位置 | 职责 |
| --- | --- | --- |
| 访客助手 | Unraid / Linux Docker | 登录学校系统、同步预约、展示二维码、自动续约、发送 Telegram 通知 |
| Cloud Mail | Cloudflare，单独部署 | 接收学校来信，提供邮箱账号和收件 API |
| 访问入口 | 浏览器 / iOS 快捷指令 | 查看门禁码、配置续约、阅读来信 |

Docker 设备需要能访问学校访客系统、收件接口，以及启用通知时的 Telegram API。手机通过同一内网或已有的远程访问方式连接助手；HTTPS 可由反向代理提供。

## 环境变量

在项目根目录的 `.env` 中配置：

| 变量 | 默认值 / 示例 | 作用 |
| --- | --- | --- |
| `MAIL_API_URL` | `https://mail.example.com` | Cloud Mail 站点的 HTTPS 地址，不带 `/api` |
| `MAILBOX_ADDRESS` | `visitor@inbox.example.com` | 与学校访客账号一致的收件邮箱 |
| `SYNC_SECONDS` | `300` | 后台同步间隔，范围 60–3600 秒 |
| `BIND_ADDRESS` | `0.0.0.0` | 宿主机监听地址 |
| `HTTP_PORT` | `8789` | 宿主机访问端口 |
| `TELEGRAM_BOT_TOKEN` | 留空 | Telegram Bot Token，与聊天 ID 一起填写后启用通知 |
| `TELEGRAM_CHAT_ID` | 自己的数字聊天 ID | Telegram 通知接收会话 |

助手访问密钥为 `.secrets/app-key`，Cloud Mail 邮箱账号的登录密码为 `.secrets/mailbox-password`。助手通过邮箱密码取得登录令牌，并在令牌到期后自动重新登录。

## 自动续约

所有日期和时间按北京时间计算，网页“可选配置”支持：

| 配置 | 默认行为 |
| --- | --- |
| 自动续约 | 开启，访客信息配置完整后参与调度 |
| 工作日算法 | 中国法定工作日，包含调休；也可选周一至周五 |
| 提前天数 | 到期前 3 个工作日，可设 1–10 天 |
| 续约时间 | 09:00，可选 0–23 点；在到点后的同步中执行 |
| 日期范围 | 从续约当天起取学校允许的最大跨度；也可选到期次日接续 |
| 预约内容 | 门岗、原因、补充说明、接访人邮箱、驾车与车牌 |

例如原预约到 2026 年 11 月 14 日，提前 3 个法定工作日的触发日期为 11 月 11 日。假设当日学校允许提前 15 天、单次跨度 16 天，则最大跨度模式申请 11 月 11–26 日，接续模式申请 11 月 15–26 日。实际日期还会根据学校当前的禁约日期、星期和当天预约设置调整。

待审批预约会显示为等待审批，学校批准后继续跟踪有效期。每次申请的日期和提交状态保存在 `data/renewal-ledger.json`。页面显示“上次提交结果待核实”时，先在学校记录中核对申请，再处理本地记录。

法定工作日数据位于 `calendar/`，当前包含 2025–2027 年，文件内保留国务院通知链接。更新下一年的文件后，在 `agent/main.mjs` 的加载年份中加入该年，并同步更新 `test/renewal.test.ts` 的年份和测试。缺少年份时，页面显示相应状态，补齐数据后恢复调度。

## Telegram 通知

1. 创建自己的 Telegram 机器人，并在聊天中点击 Start。
2. 在 `.env` 中填写 Bot Token 和数字聊天 ID：

```dotenv
TELEGRAM_BOT_TOKEN=你的BotToken
TELEGRAM_CHAT_ID=你的数字聊天ID
```

重新构建并启动：

```sh
docker compose up -d --build
```

两项留空时关闭通知，填写后由主 Compose 配置传入服务。服务在本次自动续约的全部可预约日期获批后发送通知，消息包含批准日期范围。发送状态随续约记录保存，通知失败会在后续同步中重试。若消息已送达而本地保存失败，恢复后可能补发一次。

## 更新与备份

将 `data/`、`.secrets/` 和 `.env` 一起备份，分别包含运行状态、密钥和部署配置。升级前保留旧镜像及对应的数据备份。

取得新版源码后重新构建：

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail 30
```

容器健康检查对应 HTTP 进程状态；网页和 `GET /api/visitor/status` 展示学校同步、二维码及续约进度。

## 常见状态

| 状态 | 处理方式 |
| --- | --- |
| 首次同步中 | 通常等待 30–120 秒，完成验证码登录和预约读取 |
| 今天没有已批准预约 | 在学校查看当天预约和接访人审批状态 |
| 二维码需要刷新 | 点击“刷新预约”，或按 [API 文档](api.md) 发起刷新 |
| 验证码等待超时 | 检查 Cloud Mail 收件、邮箱账号密码和学校来信 |
| 学校连接失败 | 从 Docker 宿主机检查学校地址的连通性 |
| 缺少节假日数据 | 补齐对应年份并重新构建 |
